# Overnight batch, 2026-08-23/24 — raw results

Two GPUs, ~18 h. All cells LIBERO `libero_spatial`, 200 episodes (X-VLA 190),
official init states, RTN unless stated.

## 1. OpenVLA-OFT: the whole W4A8 collapse is one 28,672-parameter layer

Action head = 4 linears (`fc1`, two `mlp_resnet_blocks.*.ffn.1`, `fc2`).
Baseline 95.0 %.

| quantized | params | success | Δ |
|---|---|---|---|
| `fc1` | 117,440,512 | 96.0 | +1.0 |
| both resnet blocks | 33,554,432 | 93.5 | −1.5 |
| **`fc2`** | **28,672** | **19.5** | **−75.5** |
| `fc1`+`fc2` | 117,469,184 | 19.0 | −76.0 |
| all four | 151,023,616 | 20.5 | −74.5 |

`fc2` is 512→56 (8 action chunks × 7 dims): the projection whose output *is*
the action. 99.98 % of the head's parameters quantize to W4A8 for free; the
remaining 0.02 % costs 75 points.

### It is the activations, not the weights

| setting | success |
|---|---|
| baseline | 95.0 |
| W4 weight-only, whole head | 94.0 |
| W4A8 | 20.5 |
| W8A8 | 36.0 |
| W4A4 | 0.0 |

4-bit weights are free; adding 8-bit activations collapses the policy;
relaxing the weights back to 8 bits recovers only 15.5 points.

## 2. π0.5: non-additivity, measured over ten subsets of the same component

W4A4 on the action head, baseline 87.5 %. 167 quantizable layers =
18 blocks × (4 attn + 3 mlp + 2 adaRMS) + 5 plumbing layers.

| quantized subset | layers | success | Δ |
|---|---|---|---|
| attention only | 72 | 84.5 | −3.0 |
| adaRMS only | 36 | 68.5 | −19.0 |
| **attention + adaRMS** | **108** | **15.0** | **−72.5** |
| `gate_proj` only | 18 | 81.0 | −6.5 |
| `up_proj` only | 18 | 85.0 | −2.5 |
| `down_proj` only | 18 | 24.5 | −63.0 |
| MLP (gate+up+down) | 54 | 27.5 | −60.0 |
| MLP + adaRMS | 90 | 21.5 | −66.0 |
| `down_proj` + attention | 90 | 18.0 | −69.5 |
| `down_proj` + attn + adaRMS | 126 | 12.0 | −75.5 |
| everything except adaRMS | 131 | 32.0 | −55.5 |
| **everything** | **167** | **49.5** | **−38.0** |

Two independent violations of additivity, in opposite directions:

* **Synergy.** Attention alone costs 3.0 and adaRMS alone costs 19.0, but the
  two together cost 72.5 — 50 points more than the sum of the parts, with no
  MLP quantized at all.
* **Protection by co-quantization.** `down_proj`+attn+adaRMS (126 layers)
  scores 12.0; adding `gate_proj` and `up_proj` — which cost 6.5 and 2.5 on
  their own — brings the same 126 layers plus 41 more up to 49.5. Quantizing
  *more* recovers 37.5 points. Neither endpoint is at the floor, so this is
  not a saturation artefact.

Any mixed-precision search that scores layers or components independently and
sums is measuring the wrong quantity on this model.

## 3. π0: the same backbone, none of the same structure

Baseline 61.5 %. W4A4 on the action head.

| quantized | layers | success | Δ |
|---|---|---|---|
| `gate_proj` only | 18 | 62.0 | +0.5 |
| `up_proj` only | 18 | 61.0 | −0.5 |
| `down_proj` only | 18 | 61.0 | −0.5 |
| MLP (all three) | 54 | 55.5 | −6.0 |
| attention only | 72 | 61.0 | −0.5 |

π0 and π0.5 share the PaliGemma + Gemma-expert architecture and differ mainly
in adaRMS conditioning. `down_proj` dominance is worth 63 points on π0.5 and
0.5 points on π0 — so it is **not** an architectural property, and the small
MLP effect π0 does have is itself non-additive (three parts ≈ 0 each, whole
−6.0).

## 4. Two mechanisms proposed, both refuted by the data

**"The final action projection is the bottleneck."** OFT's `fc2` and π0.5's
`action_out_proj` play the same role, are nearly the same size, and behave in
opposite ways:

| model | layer | params | setting | Δ |
|---|---|---|---|---|
| OpenVLA-OFT | `fc2` | 28,672 | W4A8 | −75.5 |
| π0.5 | `action_out_proj` | 32,768 | W4A4 (harsher) | 0.0 |
| π0.5 | `action_out_proj` | 32,768 | W4A8 | −2.0 |
| π0 | `action_out_proj` | 32,768 | W4A4 | −5.5 |

**"Flow matching averages the error away."** π0.5 integrates its output over
`num_inference_steps` denoising steps, so per-step error could cancel. It does
not: with its own matched unquantized control at each setting,

| denoising steps | control | `action_out_proj` at W4A4 | Δ |
|---|---|---|---|
| 10 (default) | 87.5 | 87.5 | 0.0 |
| 2 | 89.0 | 93.0 | +4.0 |
| 1 | 89.0 | 87.0 | −2.0 |

At one step there is nothing to average, and the layer is still free to
quantize. Few-step inference does not degrade the policy on its own either
(89.0 at both 1 and 2 steps), so the controls are clean.

## 5. Can a rollout-free statistic predict which layer breaks?

`scripts/act_diagnostics.py` probes every quantizable layer during two real
episodes and records, on the activations the policy actually sees: per-token
absmax dispersion, kurtosis of |x|, the activation grid's own relative error,
and the relative output error the quantized layer produces.
`scripts/diag_vs_damage.py` pairs each ablation cell with the layers that cell
recorded quantizing (read from its `--only` patterns, not re-derived by hand)
and rank-correlates.

| | cells | kurtosis | out_rel_err | act_rel_err |
|---|---|---|---|---|
| within π0.5 | 13 | +0.610 | +0.571 | +0.555 |
| within π0 | 6 | +0.143 | +0.429 | +0.257 |
| pooled | 19 | +0.612 | +0.667 | +0.735 |

Moderate, and not a substitute for measurement. π0's row carries no
information — every π0 cell lands between 0 and 6 points of damage, so there
is almost no ordering to recover. And there is a flat counterexample: π0's
`down_proj` has kurtosis 229 and costs 0.0 points, while π0.5's has kurtosis
314 and costs 63.0. A statistic that ranks layers usefully *within* a model
but not *across* models is a per-model triage tool, not a transferable law —
which is the same conclusion the rollout data reaches by a different route.

## Note on scope coverage

X-VLA's action decoder is `nn.Embedding`-style per-domain weight lookup
(`transformer.action_decoder.fc`, (30, 20480)), not `nn.Linear`, so the
quantizer does not touch it. X-VLA's `ah` scope therefore covers the 24
transformer blocks and two input projections but **not** its output
projection — which, given §1, is exactly the layer that matters elsewhere.
This is a limitation of the current implementation, not a property of X-VLA.

## Retracted: X-VLA "attention only"

An earlier cell reported that quantizing X-VLA's action-head attention alone
cost exactly 0.0 points. It quantized **zero layers**: the pattern was
`*self_attn*`, which is the Gemma/LLaMA name. X-VLA calls them
`transformer.blocks.N.attn.qkv` and `.attn.proj`, so nothing matched and the
run silently re-measured the baseline — which is precisely why it reproduced
the baseline to the decimal.

The result has been deleted and re-queued with `*attn.qkv*` / `*attn.proj*`
(48 layers). `scripts/verify_cells.py` now refuses any RTN cell whose header
records zero quantized layers, and the runner script gates each task on the
*exact* expected layer count rather than merely a nonzero one.

Two lessons, both already paid for once:

* A `--only` pattern that matches nothing is indistinguishable from a baseline
  run unless the layer count is checked. An ablation that "shows no effect" is
  the single most likely place for this to hide.
* `grep -c` prints `0` *and* exits non-zero when there are no matches, so
  `n=$(grep -c ... || echo 0)` yields `"0\n0"` and the following integer test
  errors out instead of failing — an empty cell can be logged as DONE. Every
  number in this document comes from `scripts/verify_cells.py` reading the
  files, not from the queue logs.
